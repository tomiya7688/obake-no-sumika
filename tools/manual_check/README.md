# 実画面確認キット

Issue #123。本人（Kadoka）に実画面の確認を頼むための仕組み。

## 本人の使い方

1. リポジトリ直下の `run_manual_check.bat` をダブルクリックする（初回だけ、先に `run_object_editor.bat` を一度起動して準備を済ませる）。
2. 左の一覧から、エージェントに言われた項目を選ぶ。
3. 「エディターを開く」を押し、右に出る手順を上から順に操作する。
4. 期待どおりなら「できた」、違ったら「違った」を選び、気づいたことをメモに書く。
5. 「結果を保存」を押す。エージェントが結果を読むので、チャットに書き写す必要はない。

エディターは確認用のコピーだけを開く（`conversations.json` など、リポジトリのデータは開かない）。うまく開けない時は、出てきたメッセージをそのままエージェントに伝える。

## エージェント向け

- 確認項目は `script/manual_check.py` の `SCENARIOS`。1件は「データの準備（コピーを書き換える関数）・開くエディター・手順（操作と期待する表示）」。手順の文はエディターの実際のボタン名・見出しに合わせる。
- エディターのコードもデータも、git の `HEAD` からコピーしてそのコピーを起動する（作業ツリーの未コミット変更は入らない。確認したい変更はコミットしてから頼む）。置き場は環境変数 `OBAKE_MANUAL_CHECK_DIR`、なければ `E:/program_files/soft/claude/tmp/obake_manual_check/`。どちらも無い時は C ドライブに置かず、設定を求めるエラーを出す。画面の下に実際の置き場を表示する。
- 結果はその置き場の `results.json` に追記される（項目・Issue番号・コピー元のコミット `head`・時刻・エディターを開いたか・コピーの場所・手順ごとの `ok` / `ng` / 未回答 `null` とメモ）。読む時は、`head` が確認したいコミットと一致する最新の記録だけを採る。未回答や `editor_opened: false` は確認済みとして扱わない。
- `run_manual_check.bat` は共通の起動口（`tools/security/script/launch.py`）を通さず、既存の `.venv` の Python を直接使う。起動口の対象一覧は security ツール側で固定されているため。venv の準備・更新中（`.venv-setup.lock` がある間）は使わない。
- 確認用コピーは開くたびに作られ、14日より古いものは次に開いた時に消える（`results.json` は残る）。
- 確認を頼んで「次へ」と返された時は、手順が分かりにくいという意味。項目の文や準備を直して頼み直す（[共同作業ルール](../../docs/ワークフロー/共同作業ルール.md)）。
