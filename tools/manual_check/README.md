# 実画面確認キット

Issue #123。本人（Kadoka）に実画面の確認を頼むための仕組み。

## 本人の使い方

1. リポジトリ直下の `run_manual_check.bat` をダブルクリックする（初回だけ、先に `run_object_editor.bat` を一度起動して準備を済ませる）。
2. 左の一覧から、エージェントに言われた項目を選ぶ。
3. 「エディターを開く」を押し、右に出る手順を上から順に操作する。
4. 期待どおりなら「できた」、違ったら「違った」を選び、気づいたことをメモに書く。
5. 「結果を保存」を押す。エージェントが結果を読むので、チャットに書き写す必要はない。

本物のデータ（`conversations.json` など）は変わらない。エディターは確認用のコピーを開く。

## エージェント向け

- 確認項目は `script/manual_check.py` の `SCENARIOS`。1件は「データの準備（コピーを書き換える関数）・開くエディター・手順（操作と期待する表示）」。手順の文はエディターの実際のボタン名・見出しに合わせる。
- コピーは git の `HEAD` から取り出す（作業ツリーの未コミット変更は入らない）。置き場は環境変数 `OBAKE_MANUAL_CHECK_DIR`、なければ `E:/program_files/soft/claude/tmp/obake_manual_check/`、それもなければ OS の一時フォルダー。
- 結果はその置き場の `results.json` に追記される（項目・Issue番号・時刻・コピーの場所・手順ごとの `ok` / `ng` / 未回答とメモ）。
- 確認を頼んで「次へ」と返された時は、手順が分かりにくいという意味。項目の文や準備を直して頼み直す（[共同作業ルール](../../docs/ワークフロー/共同作業ルール.md)）。
