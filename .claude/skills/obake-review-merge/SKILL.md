# PRを判定してマージする

ルール本文は `docs/ワークフロー/レビュー基準.md`。この手順は入口だけ。

1. `docs/ワークフロー/レビュー基準.md` のレビュー観点を上から確認する。
1a. 同文書の「外部レビュー」に従い、7者とCopilot・CodeRabbitへ依頼し、結果または省略理由をPRに記録する。有効な指摘は直す。
2. `gh pr checks <番号>` で全チェックが pass であることを確認する（チェック名はレビュー基準の取り込み条件を参照）。実行中なら待つ。失敗ならマージしない。
3. `git fetch origin` し、PRが `work` より遅れていれば `origin/work` を取り込んで再評価・CI再確認する。
4. レビュー基準の「判定の記録」の形でPRにコメントする。
5. 取り込み条件をすべて満たしたら `gh pr merge <番号> --merge`。
6. ローカルの `work` を ff-only で更新し、完了条件をすべて満たしたIssueだけ手動で閉じる（`work` 宛てPRの `Closes` は自動で閉じない）。
