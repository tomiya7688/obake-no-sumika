# プロジェクト定義の共有契約 v1

対象はプロジェクト定義の読込だけ。Python / Godot / Unityで共有する入力・正規化結果・拒否条件をここから確認できる。起動方法、各コンテンツの意味検証、ゲームの挙動は対象外。Godot / Unityの実装や検証済みランタイムを提供する文書ではない。

## 入力

UTF-8 JSONのオブジェクトを読む。プロジェクトルートは、指定されたプロジェクト定義ファイルの親ディレクトリ。ファイル名は固定しない。

| フィールド | 新規データの形式 | 省略時 / 読込結果 |
| --- | --- | --- |
| `schema_version` | `1` | 必須。未対応バージョンは拒否 |
| `name` | 空白だけでない文字列 | 必須。前後の空白を除去 |
| `project_type` | 内部に空白を含まない非空文字列 | 省略または `null` は `standard`。前後の空白を除去。未知の種類も保持 |
| `entrypoint` | 存在するファイルへのパス | 必須。拡張子による判定はしない |
| `editors` | `id`, `label`, `script` を持つオブジェクトの配列 | 省略は空配列。順序を保持 |
| `content_manifest` | コンテンツ定義ファイルへのパス | 省略または `null` は外部定義なし |
| `content` | コンテンツ名とパスの対応オブジェクト | 省略は空オブジェクト。旧形式との互換用 |

エディターの `id` と `label` は前後の空白を除去し、空なら拒否する。正規化後の `id` は一意。`script` は存在するファイルでなければならない。

外部コンテンツ定義もオブジェクトで、`schema_version: 1` が必須。`content` は省略でき、省略時は空オブジェクト。コンテンツ名は前後の空白を除去し、空なら拒否する。参照先はファイルでもディレクトリでもよい。

未知のフィールドは無視する。新規データでは表の型を使う。現Python版には名前などの非文字列を文字列化する互換挙動もあるが、非文字列の文字列表現は言語依存なので、この移植用テストケースの対象にしない。`schema_version` は新規データで整数 `1` を使う。

## パスと統合

1. 新規データには、プロジェクトルートからの相対パスを `/` 区切りで保存する。
2. パスは非空文字列で、解決後に存在する必要がある。`..` やシンボリックリンク等を解決した実際の参照先がルート外なら拒否する。ルートそのものはコンテンツ参照に使えるが、ファイル指定には使えない。
3. 外部コンテンツ定義がサブディレクトリにあっても、その中の参照パスは**プロジェクトルート**から解決する。外部定義ファイルの親からではない。
4. 外部 `content` とインライン `content` の両方を検証した後、インラインの同名項目で上書きする。上書きされる外部パスも、不正なら拒否する。

現Python版はルート内の絶対パスも受理する。環境に依存するため新規データと移植用ケースには使わない。OSごとの区切り文字、大小文字、リンクの作成権限には依存せず、各ランタイムで実パスのルート内制約を別途確認する。

## 正規化結果

受理した場合は `schema_version`, `name`, `project_type`, `entrypoint`, `editors`, `content`, `content_manifest` を返す。内部で絶対パスを保持してもよいが、比較用にはパスをルート相対・`/` 区切りに戻す。外部定義なしの `content_manifest` は `null`。エディター順序は比較対象、JSONオブジェクトのキー順序は比較対象外。

読込失敗時は受理結果を返さない。エラーメッセージや例外の型は言語固有なので一致を要求しない。読込でスクリプトを実行したり、JSONを書き換えたりしない。

## 言語非依存のテストケース

正本は [project_manifest_cases.json](project_manifest_cases.json)。実装別テストは同じJSONを使う。

- `schema_version` はテストケース形式の版で、プロジェクト定義の版とは別。
- `files` は全ケース共通の仮想ファイルツリー。値が文字列ならそのままUTF-8ファイルに、その他ならUTF-8 JSONファイルにする。`directories` は空ディレクトリの一覧。
- 各ケースは `id`, `manifest`, `expected` と任意の `files` を持つ。ケースの `files` は共通ファイルを追加・上書きする。毎回独立したツリーにする。
- `manifest` をルートの `engine_project.json` に保存し、読込を呼ぶ。ルートの外に `outside.entry` も作り、外部参照を拒否できることを確認する。
- `expected.status` が `accepted` なら `expected.result` と正規化結果全体を比較する。`rejected` なら読込失敗を確認する。

Python版のアダプターは `tests/test_portable_project_contract.py`。GUI、pygame、実際のゲーム画像、外部サービスは不要。

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_portable_project_contract -v
```

形式を変える時は文書・ケース・各実装のアダプターを一緒に更新する。ケース追加だけで未実装言語の互換性を保証したと扱わない。
