# 配布物の検証手順

Refs #122, #100

## 生成される成果物

| 種類 | ファイル名 | 中身 |
|---|---|---|
| ゲーム本体 | `obake-no-sumika-game-v<VERSION>.zip` | `game.py`、`engine/`、ゲームデータ、`run_game.bat` など |
| エディター類 | `obake-no-sumika-editors-v<VERSION>.zip` | `engine_app.py`、各エディター、`engine/`、編集対象データ、起動 bat |
| チェックサム | `SHA256SUMS` | 上の2つの zip の SHA-256 |

中身の一覧は `tools/release/release_manifest.json` が正本です。zip は
`python tools/release/build_release.py --output-dir dist` で、ファイル順・時刻・権限を固定して
同じバイト列で再生成できます。

## 生成のしかた

`.github/workflows/release-artifacts.yml` が、タグ `v*` の push と手動実行で動きます。

1. VERSION とタグの一致、再現性、`SHA256SUMS` を確認する。
2. 2つの zip と `SHA256SUMS` に Artifact Attestation（OIDC keyless）を付ける。
3. 同じジョブで `gh attestation verify` が成功することを確認する。
4. 成果物を Actions の Artifact に置く。**GitHub Release への添付・公開は自動では行いません。**
   公開は Kadoka の確認後に手動で行います。

秘密鍵・証明書は使いません（keyless のためリポジトリに置きません）。

## 利用者の検証手順

[GitHub CLI](https://cli.github.com/) を使います。

```bash
sha256sum --check SHA256SUMS
gh attestation verify obake-no-sumika-game-v<VERSION>.zip --repo tomiya7688/obake-no-sumika
gh attestation verify SHA256SUMS --repo tomiya7688/obake-no-sumika
```

Windows では `sha256sum` の代わりに `Get-FileHash -Algorithm SHA256 <ファイル>` を使い、
`SHA256SUMS` の値と見比べます。

## 対象外

この成果物は exe を含まないため、次は対象外です。

- Windows の Authenticode 署名
- macOS の codesign / notarization
- Android の APK / AAB 署名

exe など実行ファイルを配布する場合は、#100 に従って別途対応します。
