# レビュー基準

`work` 宛てPRのレビューと取り込み判定の基準。人間・AIエージェントのどちらがレビューしても同じ基準を使う。

## 位置づけ

- 通常開発の `work` 宛てPRは、作成したエージェント自身の自己レビューで取り込んでよい（Kadoka本人の方針、2026-10-22）。
- ただし **Work CI の成功確認は必須**。ローカル評価の成功だけでCI成功と扱わない。
- `main` 反映・タグ・リリースは対象外。本人の確認・承認を待つ（[main/work統合](main_work統合.md)）。

## 取り込み条件

次をすべて満たした時だけ `work` へマージする。1つでも欠けたらマージしない。

| 条件 | 確認方法 |
| --- | --- |
| Work CI が成功している | `gh pr checks <番号>` で全チェックが pass（現在は `Work validation (Python 3.10 / Godot 4.7.2)` と `Ruff lint baseline (Python 3.10)`）。pending の間は待つ |
| 最新の `work` を含む状態でCIが通っている | マージ前に `git fetch origin` し、PRが `work` より遅れていれば `origin/work` を取り込み、CIを再実行する |
| ローカル全体評価が成功している | `scripts/evaluate_project.py --require-godot --frames 900`。Windowsでは `GODOT_BIN` に `*_console.exe` を指定する（GUI版は標準出力が空になり実Godotテストが失敗する）。Godotを使えない環境ではその旨をPRに書く |
| Ruff lint が0件 | `tools/quality/script/check_ruff.py` |
| Issueの完了条件に対応している | 未対応の条件があればPRに `Refs #番号` と残作業を書き、Issueを閉じない |
| 届いている指摘・保留指示がない | PRのレビュー・コメント、Issueの最新コメントを確認する |
| 今回の変更だけが入っている | `git diff --stat origin/work...HEAD` に無関係なファイルがない |

## レビュー観点

上から順に確認する。該当しない観点は飛ばしてよい。

1. **正しさ**: Issueの再現手順で不具合が直るか。境界値、空データ、失敗時の経路を確認する。
2. **データ保全**: JSONを黙って削除・変換しない。UTF-8の読みやすい形式を保ち、エディターで再編集できる。保存は原子的に行う。
3. **ゲームの不変条件**: [開発契約](../ai-development-contract.md) の Project contract に反しない（2匹の独立乱数、前向き移動、会話中の整列、吹き出しを重ねない など）。
4. **ランタイム間の整合**: Python版とGodot版で同じ契約を持つ処理は、片方だけ変えていないか。共有仕様は `spec/` と共有テストを正とする。
5. **テスト**: 不具合修正には回帰テストを追加する。テストは変更前なら失敗する内容にする。
6. **範囲**: 1 PR = 1 Issue。ついでの整形・リファクタを混ぜない。
7. **文書**: 機能・手順・データ契約が変わったら、対応する `docs/context/`、機能説明書、`key_info.md` を同じPRで更新する。
8. **共有ルール**: 作業手順やレビュー方法を変えたら、[共同作業ルール](共同作業ルール.md) に従って共有文書とエージェント定義を更新する。

## 指摘の重さ

| 区分 | 意味 | 扱い |
| --- | --- | --- |
| blocker | データ消失、クラッシュ、不変条件違反、CI失敗、完了条件未達のClose | 直すまでマージしない |
| should | 回帰テスト不足、文書の更新漏れ、分かりにくいエラー表示 | 原則このPRで直す。後回しにする場合はIssueを作りPRに番号を書く |
| nit | 命名・コメントの好み | 任意。直さなくてもマージしてよい |

## 証拠の区別

PRの「検証」欄では、何で確かめたかを区別して書く。区別できない書き方（「動作確認済み」だけ）はしない。

| 証拠 | 例 | これだけでは言えないこと |
| --- | --- | --- |
| 静的検査 | py_compile、Ruff | 動作の正しさ |
| 単体テスト | `unittest` | 実際の画面・操作 |
| 自動実行 | `game.py --test-frames 900`、Godot headless | 見た目・操作感 |
| CI | Work CI | 実GUIの見た目・操作 |
| 実画面確認 | `run_game.bat`、各エディターを実際に操作 | — |

UI・描画・ダイアログを変えたPRで実画面を確認できなかった場合は、PRに「実画面未確認」と書く。マージは可能だが、確認待ちの項目としてIssueかPRコメントに残す。

## 判定の記録

マージ前に、PRへ次の形のコメントを残す（自己レビューでも省略しない）。

```text
自己レビュー: マージ可
- CI: pass（<実行URL>）
- ローカル評価: ALL CHECKS PASSED（--require-godot --frames 900）
- 完了条件: すべて対応 / 残り: <内容>
- 未確認: <実画面未確認など。なければ「なし」>
- 指摘: blocker 0 / should 0
```
