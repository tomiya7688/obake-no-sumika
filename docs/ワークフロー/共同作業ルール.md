# 共同作業ルール

複数のAIエージェント（Codex、Claude など）と人間が同じリポジトリを同時に開発するための共通ルール。どのエージェントもこの文書を正とする。

## 正本

- ルール・手順の正本はリポジトリ内の共有文書（`AGENTS.md`、`docs/ワークフロー/`、`docs/context/`）。
- エージェント個別のメモリや設定は補助。そこにだけ書いたルールは他のエージェントに届かないので、正本にしない。
- 開発予定・進捗の正本は GitHub Issues。

## 共有ルールの更新義務

- 運用・手順・レビュー方法・役割が変わったら、**その場で**共有文書を更新する。後でまとめて直さない。
- 更新対象: `AGENTS.md`、この文書、[役割別ワークフロー](役割別ワークフロー.md)、[レビュー基準](レビュー基準.md)、[ワークフロー](ワークフロー.md)、エージェント定義（`.claude/agents/`）とスキル（`.claude/skills/`）。
- エージェント定義・スキルは共有文書への短い入口にし、ルール本文を重複させない。食い違ったら共有文書を正とし、定義側を直す。
- 本人（Kadoka）から口頭・チャットで受けた運用指示は、日付つきで該当文書へ書き写す。

## 着手前

1. `git fetch origin` し、`gh pr list --state open` と `git branch -r` で、同じIssue・同じファイルを触る作業が進んでいないか確認する。
2. 対象Issueの最新コメントを読む。他のエージェントが着手表明していれば、そのIssueには手を出さない。
3. 着手するIssueにコメントで表明する。

```text
着手: <エージェント名> / branch: issue/<番号>-<短い名前>
```

4. 作業を中断・放棄する時もIssueにコメントし、残作業とブランチの状態を書く。

## ブランチと作業ツリー

- 1 Issue = 1 ブランチ = 1 PR。ブランチ名は `issue/<番号>-<短い名前>`。
- 他のエージェントのブランチへ push しない。直したい点はPRコメントかIssueで伝える。
- 同じチェックアウトを共有している場合、他者の未コミット変更を stage・revert・上書き・削除しない。作業開始時の `git status` に出ていた無関係な変更は最後まで残す。
- 並行作業が多い時は `git worktree` で別ディレクトリに分ける。

## 衝突しやすいファイル

次のファイルは複数の作業が同時に触りやすい。変更は小さくし、マージ直前に最新の `work` を取り込んでから評価・CIをやり直す。

| ファイル | 理由 |
| --- | --- |
| `AGENTS.md`、`docs/ワークフロー/*`、`docs/context/*` | 全エージェントの入口 |
| `conversations.json`、`placed_objects.json`、`characters.json` | 内容の編集が人間・エディター・エージェントから入る |
| `.github/workflows/*`、`scripts/evaluate_project.py`、`tools/quality/*` | 全PRの合否に効く |
| `game.py`、`godot/scripts/*` | ゲーム本体 |

競合した時は `origin/work` をブランチへマージして解消し、他者の変更意図を消していないか差分で確認する。判断できない時は本人に確認する。

## マージ

- [レビュー基準](レビュー基準.md) の取り込み条件を満たした時だけマージする。Work CI の成功確認は必須。
- マージ後、ローカルの `work` を `git merge --ff-only origin/work` で更新する。
- `Closes #番号` は `work` 宛てPRでは自動で閉じない。完了条件をすべて満たした時だけ、手動でIssueを閉じる。

## 引き継ぎ

- 残作業・未確認事項・判断待ちは、PR本文かIssueコメントに書く。会話ログやエージェントのメモリに残すだけにしない。
- 他のエージェントの作業を引き継ぐ時は、そのPR・Issueの最新コメントから読む。

## 本人の判断が必要なもの

次は自動で進めず、本人に確認する。

- `main` への反映、タグ、リリース公開
- ゲームの仕様・見た目の方針が文書から決められない時
- データの破壊的な移行（既存JSONの項目削除・形式変更）
- 他のエージェントとの方針の食い違い
